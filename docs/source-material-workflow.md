# Source Material Workflow

This site is public, so raw source material should be handled carefully.

Use `private-source-materials/` for raw PDFs, screenshots, notes, prompts, drafts, and app captures that may include private customer, company, vendor, or internal workflow details. That folder is ignored by Git and should not be published.

Use `assets/` only for public-approved images and files that are safe to publish on the live site. Sanitized project screenshots should go under `assets/portfolio-previews/`.

When turning raw material into site content:

1. Extract the useful truth.
2. Remove private names, customer details, sensitive operational details, and over-specific internal process notes.
3. Convert the material into short public-safe proof points.
4. Add only the polished public-safe copy or approved assets to the site.
5. Keep the public wording honest about whether the work is finished, private, prototype-stage, or actively evolving.
