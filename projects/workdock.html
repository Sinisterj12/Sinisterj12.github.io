Current daily-driver · operator workspace

WorkDock

A Windows-first command center for people who live in Google Workspace and local files all day. I built it around the way support, sales, installation, and operations work actually happens: Gmail, Sheets, Drive, downloaded files, notes, repeated contexts, and multiple monitors.

Google WorkspaceDesktop operationsLocal contextPrivacy boundariesHuman-controlled workflow

The problem

Daily work gets fragmented before AI even enters the picture.

Operators bounce between Gmail, Sheets, Drive, Downloads, File Explorer, scratch notes, and repeated browser layouts. The first problem is not “how do I add an agent?” It is how to reduce context switching without destroying the tools people already trust.

System shape

Keep the familiar tools. Build a better operating shell around them.

Workspace dockGmail, Sheets, Docs, Drive, Calendar, Meet and Chat stay recognizable and directly accessible.
Local file awarenessRecent Downloads and local Google Drive destinations remain close to the active workflow.
Context-aware notesQuick Note begins blank, saves only what the user types, and can attach deterministic context such as Sheets, Gmail, Customer, Install or Task.
Session separationWorkDock maintains its own app/session profile rather than sharing normal Chrome, Edge or Firefox browser state.

Trust boundaries

Useful context without silent data harvesting.

The product intentionally avoids scraping email bodies, sheet contents, page HTML, passwords, cookies, tokens or credentials into notes. Portable configuration is designed to exclude sessions and machine-specific paths. That boundary matters because “context-aware” software becomes dangerous quickly if context collection is vague.

Why this matters for AI work

Good AI deployment often starts by fixing workflow and context first.

WorkDock demonstrates a principle I use across AI projects: do not start with autonomy. First create a clear operating surface, explicit state, safe context boundaries, and predictable user control. Once that foundation exists, AI can be introduced where it provides measurable value instead of becoming another source of chaos.

What this proves

  • I design around real repeated operator behavior rather than generic app ideas.
  • I treat privacy and context boundaries as product architecture, not fine print.
  • I preserve familiar tools when replacement would create more friction than value.
  • I think about AI as one layer in a larger human workflow.

Current use

Private daily-driver testing

This is a system I actually use. The current product is appropriate for private daily-driver testing rather than broad public release, which keeps the portfolio claim accurate while still showing a substantial real operating workflow.
