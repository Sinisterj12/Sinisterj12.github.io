AI operating principles

I design for the fact that models can be wrong.

Useful AI systems need more than good prompts. They need a trust model. My approach is to define what the model knows, what it may do, what must be verified, when it should ask instead of infer, and how a human can inspect the chain of work.

01

Human authority

Consequential decisions stay with the operator. Autonomy is granted deliberately, not assumed because a model is capable of taking an action.

02

Evidence over confidence

Runtime results, files, screenshots, tests, repository state and user confirmation outrank a persuasive AI statement that work is complete.

03

Context before intelligence

A model cannot rescue bad context reliably. Retrieval, state, system boundaries and source quality come before clever prompting.

04

Least necessary autonomy

Give an agent only the authority required for the workflow. Add explicit approval boundaries when the downside of a wrong action is meaningful.

05

Visible failure paths

Missing context, ambiguity, tool errors and partial execution should surface clearly. Good systems make uncertainty inspectable instead of masking it.

06

Durable handoffs

Important state should survive the chat or agent session that created it. Another human or model should be able to resume without reconstructing the project from memory.

From operations to AI

My workflow starts with the problem, not the model.

I spend my day inside operational systems where bad assumptions have consequences. That changes how I build with AI. The goal is to reduce real friction while keeping the workflow explainable, recoverable and safe for the people using it.

01 · Observe

Map the actual operator pain

Watch where time, context and confidence are being lost in the real workflow.

02 · Structure

Build trustworthy context

Define the data, relationships, sources and state the AI needs before asking it to reason.

03 · Bound

Set authority and fallback rules

Decide what the model may suggest, what it may execute and where human approval is mandatory.

04 · Verify

Test outcomes, not confidence

Use direct evidence, runtime checks and review paths to determine whether the system really worked.

05 · Learn

Turn failures into system improvements

Capture repeated misses as better context, instructions, evals, guardrails or workflow design.
