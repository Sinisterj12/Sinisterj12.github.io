AI operating principles

I design for the fact that models can be wrong.

Useful AI systems need more than good prompts. They need a trust model: what the model knows, what it may do, what must be verified, when it should ask instead of infer, and how a human can inspect the chain of work.

01

Human authority

Consequential decisions stay with the operator. Autonomy is granted deliberately, not assumed.

02

Evidence over confidence

Runtime results, files, screenshots, tests, repository state and user confirmation outrank persuasive model claims.

03

Context before intelligence

Retrieval, relationships, state, source quality and system boundaries come before clever prompting.

04

Least necessary autonomy

Give an agent only the authority required for the workflow and add approval gates where wrong actions matter.

05

Visible failure paths

Missing context, ambiguity, tool errors and partial execution should surface clearly instead of being masked.

06

Durable handoffs

Important state should survive the chat or agent session so another human or model can resume without guessing.

From operations to AI

My workflow starts with the problem, not the model.

I work inside operational systems where bad assumptions have consequences. That creates a strong bias toward explainable, recoverable workflows and direct evidence.

01 · Observe

Map the actual operator pain

Watch where time, context and confidence are being lost.

02 · Structure

Build trustworthy context

Define the data, relationships, sources and state the AI needs before reasoning.

03 · Bound

Set authority and fallback rules

Decide what the model may suggest, execute, or must escalate.

04 · Verify

Test outcomes, not confidence

Use direct evidence, runtime checks and review paths.

05 · Learn

Turn failures into system improvements

Convert repeated misses into better context, instructions, evals, guardrails or workflow design.
